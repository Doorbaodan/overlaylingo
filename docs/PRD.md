## 1. 产品概述

**浮译（OverlayLingo）** 是一个运行在 Windows 10/11 上的桌面翻译助手。它在屏幕最上层提供一个悬浮窗，用户在游戏、视频、漫画、小说、直播等任意画面里框选一块区域，软件持续捕获该区域画面、识别其中的文本，并调用大模型产出符合场景语境的翻译，最终以「逐句中外对照」的形式呈现；任意一句可点开做深度解析。

它不是传统的「复制→粘贴→翻译」工具，而是**覆盖在画面之上的第二层阅读层**：翻译发生在用户「看之前」，热键只负责揭开结果。

### 1.1 一句话价值

> 玩原版游戏、啃生肉漫画时，按下热键，眼前就是已经翻好的、符合世界观的对照字幕。

### 1.2 差异化

| 传统翻译工具 | 浮译 |
|---|---|
| 手动截图 → 上传 → 等待 | 后台常驻捕获，调出即见 |
| 逐句「机翻」，无上下文 | 任务级世界观/术语/语气约束 |
| 翻完即弃 | 逐句可深挖语法、俚语、文化梗 |
| 看不到成本 | 实时余额 + 本地用量账本 |

## 2. 目标用户与使用场景

### 2.1 目标用户

- 玩外文原版游戏、但语言水平不足以流畅阅读的玩家（核心用户）
- 啃生肉漫画 / 轻小说 / 外文小说的读者
- 看无字幕外文直播、视频的学习者
- 有「官方翻译不靠谱，想对照原文」需求的重度内容消费者

### 2.2 核心场景（用例）

| 场景 | 描述 | 关键诉求 |
|---|---|---|
| **游戏快速对话** | 《赛博朋克2077》英文版，屏幕下方框选字幕带，角色连续对话 | **速度**：调出窗口即已翻完 |
| **游戏长文本道具** | 拾取「数据芯片」，一大段世界观文本 | 符合世界观、逐句深解 |
| **漫画阅读** | 生肉漫画，艺术字/竖排 | 视觉模型兜底识别 |
| **小说阅读** | 导入 txt/epub，长文阅读 | 分段翻译 + 阅读器 |
| **视频 / 直播** | 外文视频字幕、直播弹幕 | 连续滚动字幕（进阶） |

### 2.3 用户故事（P0）

- 作为玩家，我可以**新建一个任务**，告诉 AI「我在玩赛博朋克2077英文原版，官方中译有偏差，请保留街头俚语质感、术语用官方译名」，让后续翻译都遵循这一语境。
- 作为玩家，我可以**在屏幕上拖拽框选一块矩形区域**（如字幕带），软件只识别这块区域里的文字。
- 作为玩家，在角色快速对话时，我**按下热键调出窗口**，刚才那段对话已经全部翻译完成、逐句对照展示。
- 作为玩家，我可以**点击任意一句译文**，展开它的详细解析（直译、意译、语法、俚语/梗、术语说明）。
- 作为玩家，我可以在软件里**看到我的 DeepSeek 剩余额度**和本次/累计消耗。
- 作为读者，我可以**导入一个 txt/epub 文件**，分段阅读并翻译。

## 3. 核心价值主张

1. **秒开**：翻译发生在你看之前（后台预热流水线）。
2. **懂语境**：任务级世界观 + 术语表 + 语气约束，不是裸机翻。
3. **能深挖**：逐句可展开语言解析，翻译同时也是学习工具。
4. **透明可控**：余额、用量、成本全程可见。
5. **隐私本地**：截图与译文只存本地，不上传（视觉兜底模式除外）。

---

## 4. 术语约定

| 术语 | 定义 |
|---|---|
| **任务（Task）** | 一次「翻译作业」的配置集合：语言方向、世界观背景、语气风格、术语表、模型档位、捕获区域 |
| **捕获区域（ROI）** | 用户框选的矩形屏幕区域，软件只识别其内文本 |
| **台词（Line）** | OCR 后经去重、合并得到的单条文本 |
| **预热流水线** | 任务激活后后台常驻运行的 捕获→OCR→缓冲→翻译 链路 |
| **详细解析（Deep Dive）** | 对单句的流式深度解读 |
| **译文缓存** | 以原文哈希为键的译文存储，命中即零成本零延迟 |
| **悬浮窗（Overlay）** | 置顶于游戏之上的译文呈现窗口 |

## 5. 功能需求

### 5.1 P0 — MVP（必须）

**F-01 任务管理**
- 新建 / 编辑 / 删除 / 切换任务
- 任务字段：名称、源语言、目标语言、世界观背景（自由文本）、语气风格（自由文本或预设）、术语表、模型档位（flash/pro）、捕获区域、快捷键、启用状态
- 任务可复制为模板

**F-02 区域框选**
- 全屏半透明遮罩，鼠标拖拽拉出矩形，可调整、可取消
- 支持多显示器，坐标系换算正确（含缩放 DPI）
- ROI 与任务绑定记忆，任务切换时自动恢复

**F-03 全局热键**
- 默认：`Alt+Q` 调出/隐藏悬浮窗，`Alt+W` 重新框选，`Alt+E` 翻译当前屏一次
- 全部可自定义；冲突时提示；游戏内可触发（经低层钩子）

**F-04 悬浮窗**
- 置顶（screen-saver 层级）、无边框、可拖拽、透明度可调
- 可切换「鼠标穿透」模式
- 逐句对照列表（原文/译文两栏），自动滚动到最新

**F-05 预热流水线（核心）**
- 任务激活即后台常驻：捕获流 → 帧差检测 → OCR → 台词去重合并 → 静默检测 → 投机翻译 → 落缓存
- 帧差：画面无变化则跳过 OCR
- 静默检测：文本稳定 ~350ms 才入队，避免翻半句

**F-06 逐句对照**
- 原文 + 译文成对展示，按时间顺序
- 支持一键导出 Markdown / JSON

**F-07 句子详情（Deep Dive）**
- 点击某句 → 抽屉面板流式输出：直译、意译、语法点、俚语/文化梗、术语说明、上下文提示
- 使用 `deepseek-v4-pro` 模型

**F-08 余额与用量**
- 状态栏实时显示 DeepSeek 余额（`GET /user/balance`），手动/自动刷新
- 本地账本：每次调用的 prompt/completion token、估算费用、累计统计
- 低额度（可配阈值）提醒

**F-09 设置**
- API Key 配置（DPAPI 加密存储）、模型选择、温度、代理、快捷键、主题、OCR 引擎（本地/视觉兜底/混合）
- 连接测试与余额校验

**F-10 数据本地化**
- 全部数据存本地 SQLite，支持导出/清空

### 5.2 P1 — 打磨

- **F-11 视觉模型兜底**：漫画艺术字、复杂排版、竖排日文走 `deepseek-flash` 图像理解通道
- **F-12 术语表自动抽取**：翻译时发现新专名，自动建议入库
- **F-13 任务模板**：预置「赛博朋克 / 日系轻小说 / 学术论文 / 影视剧」等
- **F-14 翻译记忆库（TM）**：同句哈希命中直接复用
- **F-15 小说模式**：txt/epub 导入 + 长文分段翻译 + 阅读器视图
- **F-16 悬浮球**：鼠标流触发，无需热键
- **F-17 离线降级**：断网时仍可查看历史译文

### 5.3 P2 — 进阶

- **F-18 实时同声传译**：底部持续滚动字幕条，逐句增量翻译（架构已预留）
- **F-19 本地 ASR**：whisper.cpp，无字幕游戏靠语音识别
- **F-20 多语种 OCR**：日/韩/俄、竖排
- **F-21 macOS 适配**

## 6. 非功能需求

| 维度 | 指标 |
|---|---|
| 热键→窗口显示延迟 | < 100ms（译文已预热） |
| 翻译首 token 延迟 | < 500ms（流式） |
| OCR 单帧 | < 80ms（GPU/DirectML）；英文游戏字幕准确率 > 95% |
| 后台常驻 CPU | 待机 < 5%，捕获时 < 15% |
| 内存 | < 300MB |
| 稳定性 | 连续运行 2 小时无崩溃、无泄漏 |
| 隐私 | 截图/译文仅本地；API Key 用 Windows DPAPI 加密；除视觉兜底模式外不上传图片 |
| 兼容 | Windows 10/11，D3D 游戏无边框窗口模式 |

## 7. 技术方案

### 7.1 技术栈（已定）

| 层 | 选型 |
|---|---|
| 壳 | Electron 33 + Node 22 |
| UI | React 19 + TypeScript + Vite + Tailwind CSS + Zustand |
| 窗口层 | `frame:false` + `transparent` + `alwaysOnTop('screen-saver')` + `setIgnoreMouseEvents(true,{forward:true})` |
| 热键 | `globalShortcut` + `uiohook-napi`（低层组合键） |
| 捕获 | 持久 `getUserMedia` 屏幕流 + `OffscreenCanvas` ROI 裁剪 |
| OCR | `onnxruntime-node` + RapidOCR（PP-OCRv5），跑在 Electron `utilityProcess`，**GPU 走 DirectML** |
| 大模型 | OpenAI 兼容 SDK → DeepSeek（`deepseek-flash` 默认 / `deepseek-v4-pro` 深解；`flash` 支持图像理解） |
| 存储 | `better-sqlite3` |
| 密钥 | Electron `safeStorage`（DPAPI） |
| 打包 | `electron-builder` → NSIS + portable；`electron-updater`；GitHub Actions |
| 协议 | MIT |

### 7.2 架构

三个窗口进程 + 一个 OCR 独立进程：

- **主窗口**：任务管理、设置、历史、余额
- **框选遮罩窗口**：全屏透明，负责 ROI 拖拽
- **悬浮窗**：置顶译文呈现
- **OCR utilityProcess**：隔离 onnxruntime，避免阻塞与崩溃传播

数据流（预热流水线）：

```
屏幕画面 → 捕获流(常驻, 裁ROI) → 帧差 → OCR → 台词缓冲(去重合并)
        → 静默检测 → DeepSeek 调度(流式) → 译文缓存 → 悬浮窗(热键秒开)
```

### 7.3 速度保障四机制

1. **常驻捕获流**：流只建一次，每帧仅裁 ROI（2–5ms），不重复截图
2. **帧差 + 静默检测**：画面不变跳过 OCR；文本稳定 350ms 才翻译
3. **投机翻译**：不等热键，队列有内容即发请求
4. **缓存 + 预热命中**：原文哈希查缓存；系统提示词稳定前缀，吃满缓存命中价（¥0.02/M，为未命中的 1/50）

## 8. 数据模型

数据库：`overlaylingo.db`（SQLite，`better-sqlite3`）

### 8.1 表结构

```sql
-- 任务
CREATE TABLE task (
  id            TEXT PRIMARY KEY,          -- uuid
  name          TEXT NOT NULL,
  source_lang   TEXT NOT NULL DEFAULT 'en',
  target_lang   TEXT NOT NULL DEFAULT 'zh',
  worldview     TEXT,                       -- 世界观背景（自由文本）
  style         TEXT,                       -- 语气风格
  model_level   TEXT NOT NULL DEFAULT 'flash',  -- flash | pro
  capture_region TEXT,                      -- JSON: {displayId, x, y, w, h}
  hotkeys       TEXT,                       -- JSON
  enabled       INTEGER NOT NULL DEFAULT 0,
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);

-- 术语表
CREATE TABLE glossary (
  id       TEXT PRIMARY KEY,
  task_id  TEXT NOT NULL,
  term     TEXT NOT NULL,
  translation TEXT NOT NULL,
  note     TEXT,
  source   TEXT DEFAULT 'manual',           -- manual | auto
  FOREIGN KEY(task_id) REFERENCES task(id) ON DELETE CASCADE
);

-- 翻译单元（台词 + 译文）
CREATE TABLE translation_unit (
  id           TEXT PRIMARY KEY,
  task_id      TEXT NOT NULL,
  session_id   TEXT,
  source_hash  TEXT NOT NULL,               -- 原文哈希，缓存键
  source_text  TEXT NOT NULL,
  target_text  TEXT,
  status       TEXT NOT NULL DEFAULT 'pending', -- pending|translating|done|failed
  created_at   INTEGER NOT NULL,
  FOREIGN KEY(task_id) REFERENCES task(id) ON DELETE CASCADE
);
CREATE INDEX idx_tu_hash ON translation_unit(source_hash);
CREATE INDEX idx_tu_task ON translation_unit(task_id, created_at);

-- 会话（一次对话的聚合）
CREATE TABLE session (
  id         TEXT PRIMARY KEY,
  task_id    TEXT NOT NULL,
  started_at INTEGER NOT NULL,
  ended_at   INTEGER
);

-- 用量账本
CREATE TABLE usage_log (
  id              TEXT PRIMARY KEY,
  task_id         TEXT,
  model           TEXT,
  prompt_tokens   INTEGER,
  completion_tokens INTEGER,
  cached_tokens   INTEGER,
  estimated_cost  REAL,                     -- 元，按当时价估算
  latency_ms      INTEGER,
  created_at      INTEGER
);

-- 设置（键值）
CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT
);
```

### 8.2 缓存键

`source_hash = sha256( source_lang + '|' + normalized(source_text) + '|' + task_id )`
命中即复用，不计费。

## 9. Prompt 设计

### 9.1 系统提示词（翻译）

> 你是资深游戏/影视本地化译员。以下是当前任务的翻译约束，必须严格遵守。
>
> **背景**：{worldview}
> **风格要求**：{style}
> **源语言**：{source_lang}，**目标语言**：{target_lang}
> **术语表**（术语 → 统一译名，出现时必须使用）：
> {glossary}
>
> 输出要求：忠实于原文信息，符合上述语境与语气；术语严格遵循术语表；不添加原文没有的内容；不使用敬语/翻译腔。

> 注：系统提示词保持稳定前缀，以最大化 DeepSeek 缓存命中，降低成本与首 token 延迟。

### 9.2 快速对话翻译（批量、结构化输出）

用户消息（JSON，经 `json_mode` 输出）：

```json
{
  "type": "translate_batch",
  "lines": [
    {"id": "l1", "text": "First line of dialogue."},
    {"id": "l2", "text": "Second line of dialogue."}
  ]
}
```

要求输出：

```json
{
  "translations": [
    {"id": "l1", "translation": "第一句对白。"},
    {"id": "l2", "translation": "第二句对白。"}
  ]
}
```

- 一次请求尽量合并多条台词（降低 RTT 与固定开销）
- 模型 `deepseek-flash`，非思考模式，temperature 0.3，流式

### 9.3 详细解析（单句、结构化输出）

用户消息：

```json
{
  "type": "explain",
  "source": "一句原文",
  "translation": "对应译文",
  "context": "前后几句对白，供理解语境"
}
```

要求输出：

```json
{
  "literal": "直译",
  "natural": "意译",
  "grammar": ["语法点1", "语法点2"],
  "slang_culture": "俚语/文化梗/世界观说明",
  "terminology": "涉及术语及其说明",
  "context_note": "结合语境的补充说明"
}
```

- 模型 `deepseek-v4-pro`，流式，temperature 0.7

### 9.4 视觉兜底（漫画/艺术字）

将裁剪图直接发给 `deepseek-flash`（支持图像理解）：

> 请识别图片中的文字并翻译为 {target_lang}。若为漫画请保留对白气泡顺序；输出格式同 translate_batch。

## 11. 关键用户流程

### 11.1 首次配置

1. 启动 → 引导页 → 粘贴 DeepSeek API Key
2. 点「测试并查询余额」→ 显示可用额度
3. 进入主窗口，提示「无边框窗口」注意事项

### 11.2 新建任务 → 激活

1. 主窗口点「新建任务」→ 填写名称、语言方向、世界观背景、语气、术语表、模型档位
2. 点「框选区域」→ 遮罩出现 → 拖拽 → 确认
3. 点「激活」→ 预热流水线后台启动 → 状态栏显示「已激活」

### 11.3 游戏中翻译

1. 游戏运行（无边框窗口），字幕带已在 ROI 内
2. 后台持续捕获 → OCR → 投机翻译
3. 角色对话结束，用户按 `Alt+Q` → 悬浮窗弹出，译文已就绪，末尾若有未完成句流式补齐
4. 点某句 → 详情抽屉流式解析

### 11.4 小说导入

## 15. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 独占全屏无法覆盖 | 无法翻译 | 文档明确要求无边框窗口，软件内检测并提示 |
| 游戏反作弊（内核级反作弊可能拦截注入/钩子） | 热键/捕获失效 | 仅用系统级 API（GDI/WGC、全局热键），不做注入；文档标注 |
| OCR 对艺术字/竖排准确率低 | 漫画场景失败 | 视觉模型兜底通道（P1） |
| DeepSeek 价格变动 | 成本上升 | 用量账本 + 可切换 OpenAI 兼容厂商 |
| API 限流/抖动 | 翻译延迟 | 重试 + 指数退避 + 缓存兜底 |
| Electron 体积大 | 下载慢 | 接受（打包 ~80MB），README 说明 |
| 版权 | 传播风险 | 不内置密钥、不附带受保护文本数据集 |
